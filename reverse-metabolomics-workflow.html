1.1 why Omeprazol

Omeprazole is widely used for CYP2C19 phenotyping. When administered as a racemic mixture, (R-S)-omeprazole undergoes stereoselective metabolism and is primarily metabolized to (R)-5-hydroxyomeprazole via CYP2C19/CYP3A and (S)-5-hydroxyomeprazole via CYP2C19. Cytochrome P450 2C19 (CYP2C19) enzyme is estimated to metabolize approximately 15% of all marketed drugs, among which proton pump inhibitors, antiplatelet agents, antidepressants, beta-blockers, benzodiazepines and many other compounds https://onlinelibrary.wiley.com/doi/full/10.1111/bcpt.14095

4.2 Infer adduct from observed precursor m/z

MASST reports an Adduct column, but it’s inherited from whichever library spectrum matched and does not always reflect how our compound ionised in the query data. We know the target formula per role, so for each hit we compute the theoretical m/z of a set of common adducts and pick the one closest to the observed Precursor_MZ within a ppm tolerance. This ground-truthed adduct is what we feed to SIRIUS later.

Code 
library(MetaboCoreUtils)

ADDUCT_CANDIDATES <- c(
  "[M+H]+", "[M+Na]+", "[M+K]+", "[M+NH4]+",
  "[M-H]-", "[M+Cl]-"
)

infer_adduct <- function(obs_mz, formula, ppm = 20,
                         candidates = ADDUCT_CANDIDATES) {
  if (is.na(obs_mz) || is.na(formula)) return(NA_character_)
  mass <- calculateMass(formula)
  theo <- vapply(candidates, function(a) mass2mz(mass, adduct = a)[[1]],
                 numeric(1))
  diff_ppm <- abs(obs_mz - theo) / theo * 1e6
  best <- which.min(diff_ppm)
  if (diff_ppm[best] > ppm) NA_character_ else candidates[best]
}

6.2 Resolve assay per confirmed feature

Multi-assay studies (mostly MetaboLights, sometimes Metabolomics Workbench) host several assays per dataset — different polarities, columns, or matrices. Confirmed features from different assays must NEVER be mixed: they map to different chromatography and ionisation chemistry, and therefore to different RT and m/z windows. We resolve the assay for each confirmed feature from its source_file (the MS file where SIRIUS matched the compound) and store the result in a new assay column. Every downstream filter, RT/mz summary, and EIC extraction then groups by (dataset_id, assay) so multi-assay studies stay separated.

Code 
META_DIR <- "dataset_metadata"

# --- MetaboLights ---------------------------------------------------------
# Build basename(file) → assay_file_name lookup by scanning every
# a_{ds}_*.txt assay table cached in dataset_metadata/.
mtbls_assay_lookup <- function(ds) {
  fs <- list.files(META_DIR, pattern = paste0("^a_", ds, "_.*\\.txt$"),
                   full.names = TRUE)
  if (!length(fs)) return(character(0))
  out <- character(0)
  for (fp in fs) {
    adf <- tryCatch(read.delim(fp, check.names = FALSE),
                    error = function(e) NULL)
    if (is.null(adf)) next
    file_cols <- grep("Spectral Data File", names(adf),
                      value = TRUE, ignore.case = TRUE)
    files <- unlist(lapply(file_cols, function(c) adf[[c]]), use.names = FALSE)
    files <- basename(trimws(files))
    files <- files[!is.na(files) & nchar(files) > 0]
    if (!length(files)) next
    out <- c(out, setNames(rep(basename(fp), length(files)), files))
  }
  out
}

# --- Metabolomics Workbench -----------------------------------------------
# Build per-feature AN assignment. RAW_FILE_NAME is shared across AN files
# (SUBJECT_SAMPLE_FACTORS is identical), so we disambiguate by ION_MODE
# matched against the confirmed adduct polarity, then narrow by filename
# polarity tokens when several AN files match the same mode.
mwb_assay_for_rows <- function(ds, conf_rows) {
  fs <- list.files(META_DIR, pattern = paste0("^", ds, "_AN.*\\.txt$"),
                   full.names = TRUE)
  if (!length(fs)) return(rep(NA_character_, nrow(conf_rows)))
  an_pol <- vapply(fs, function(fp) {
    ln <- readLines(fp, warn = FALSE)
    trimws(sub("^MS:ION_MODE\\s+", "",
               grep("^MS:ION_MODE", ln, value = TRUE)[1]))
  }, character(1))
  out <- rep(NA_character_, nrow(conf_rows))
  for (i in seq_len(nrow(conf_rows))) {
    adu <- conf_rows$adduct_inferred[i]
    if (is.na(adu)) next
    pol <- if (endsWith(trimws(adu), "+")) "positive" else "negative"
    candidates <- fs[grepl(pol, an_pol, ignore.case = TRUE)]
    if (!length(candidates)) next
    sf <- basename(conf_rows$source_file[i])
    if (length(candidates) > 1 && !is.na(sf) && nchar(sf)) {
      hit <- vapply(candidates, function(fp) {
        any(grepl(sf, readLines(fp, warn = FALSE), fixed = TRUE))
      }, logical(1))
      if (any(hit)) candidates <- candidates[hit]
    }
    out[i] <- basename(candidates[1])
  }
  out
}

6.3 Adduct consistency rule

For the parent/metabolite ratio to be interpretable, both compounds must be extracted using the same adduct (same ionisation chemistry, same nominal m/z offset). A dataset where omeprazole is confirmed as [M+H]+ but 5-OH-omeprazole only as [M+Na]+ is not a problem per se — both adducts are real — but the EIC windows will target different m/z values and mixing them in the ratio is confusing.

Decision rule: we restrict all diagnostic plots and downstream EIC windows to adducts that are observed in both parent and metabolite confirmed features. Adducts that appear in only one role are dropped. This does not discard entire datasets; it only drops individual features whose adduct was not replicated on the other side of the ratio.

7.1 Metadata format differences across repositories

The three repositories store sample-level metadata in very different structures, and the location of the spectral file name differs in each:

MassIVE (GNPS / Pan-ReDU)
Each dataset has a metadata TSV downloaded from Pan-ReDU (or a custom CSV from the data submitter). Both contain a SampleType column (values: "Sample", "QC", "Blank", etc.) and a filename column. TSV (Pan-ReDU): filename holds the full relative path within the MassIVE file tree, e.g. peak/05092023-pos-pc18-peaklist/pos_NA_8990_NA_NA_193_G_B5.mzXML. CSV (submitter-provided): filename holds only the bare sample stem without extension or subdirectory, e.g. pos_inf_non_10124_male_67_267_R_C8. For the CSV case, we reconstruct the full path by extracting the directory prefix and extension pattern from the MASST hit file_path entries already present in hits_curated for that dataset.
MetaboLights (EBI)
MetaboLights uses the ISA-Tab format. The study sample file (s_{id}.txt) lists sample names and phenotype factors (Characteristics[Sample type]) but contains no spectral file names. File names live in the assay file(s) (a_{id}_*.txt), which map Sample Name to Raw Spectral Data File or Derived Spectral Data File. A study may have multiple assay files — typically one per chromatographic mode (positive, negative) or matrix. We use the MsBackendMetaboLights helper mtbls_assay_data() (with an FTP fallback) to load each assay table, then match the confirmed MASST source files to determine which assay(s) are relevant. When confirmed files span more than one assay, bio_files_per_ds[[ds]] becomes a named list (keyed by assay file name) rather than a flat character vector.
Metabolomics Workbench
Data are stored in mwtab plain-text files, one per analysis (e.g., ST002044_AN003325.txt). Each contains SUBJECT_SAMPLE_FACTORS lines with tab-delimited fields: tag, subject ID, sample ID, factor string, and an optional extra field that may include RAW_FILE_NAME=.... We parse these lines across all analysis files for the study and again use confirmed source files to restrict to only the analysis/analyses that contain real data for the compounds of interest.

# Get list of assay file names from the ISA investigation file.
# Caches the investigation file locally; returns character vector of
# assay file names like "a_MTBLS1866_LC-MS_positive.txt".
mtbls_inv_assay_names <- function(ds) {
  inv_path <- file.path(META_DIR, paste0(ds, "_i_Investigation.txt"))
  if (!file.exists(inv_path)) {
    inv_url <- paste0("https://ftp.ebi.ac.uk/pub/databases/metabolights/",
                      "studies/public/", ds, "/i_Investigation.txt")
    inv_lines <- tryCatch(
      readLines(url(inv_url), warn = FALSE),
      error = function(e) { message("FTP unreachable: ", e$message); NULL }
    )
    if (is.null(inv_lines)) return(NULL)
    writeLines(inv_lines, inv_path)
  } else {
    inv_lines <- readLines(inv_path, warn = FALSE)
  }
  assay_line  <- inv_lines[startsWith(inv_lines, "Study Assay File Name")]
  if (!length(assay_line)) return(NULL)
  an <- trimws(unlist(strsplit(sub("^[^\t]+\t", "", assay_line[1]), "\t")))
  an[nchar(an) > 0]
}

# Fetch (or load cached) assay table for one assay of a MetaboLights study.
# Tries mtbls_assay_data() first (MsBackendMetaboLights); falls back to FTP.
fetch_assay_table <- function(ds, assay_name) {
  cache_path <- file.path(META_DIR, assay_name)
  if (file.exists(cache_path)) return(read.delim(cache_path, check.names = FALSE))
  adf <- tryCatch(
    mtbls_assay_data(ds, assay_name),
    error = function(e) NULL
  )
  if (!is.null(adf)) {
    write.table(adf, cache_path, sep = "\t", row.names = FALSE, quote = FALSE)
    message("  Assay file cached (mtbls_assay_data) → ", cache_path)
    return(adf)
  }
  assay_url <- paste0("https://ftp.ebi.ac.uk/pub/databases/metabolights/",
                      "studies/public/", ds, "/", assay_name)
  adf <- tryCatch(
    read.delim(url(assay_url), check.names = FALSE),
    error = function(e) { message("FTP fetch failed for ", assay_name, ": ", e$message); NULL }
  )
  if (!is.null(adf)) {
    write.table(adf, cache_path, sep = "\t", row.names = FALSE, quote = FALSE)
    message("  Assay file cached (FTP) → ", cache_path)
  }
  adf
}

8.0.1 m/z and RT window strategy

m/z: We use the median observed precursor m/z of the confirmed SIRIUS features for this dataset (stored in conf_final$mz, extracted from the actual MS2 scan headers during confirmation). We do not use the theoretical mass. Reasons:

  1. The instrument’s mass accuracy may be systematically shifted (e.g., a few ppm offset due to recalibration). The observed m/z absorbs this shift automatically.
  2. Different adducts ([M+H]+, [M+Na]+, …) give very different m/z values. Using the observed m/z means the EIC window is anchored to whichever adduct SIRIUS confirmed, without having to hard-code adduct logic here.
  3. Only adducts present in both roles are retained (see shared-adducts rule above), so the m/z we extract here is guaranteed to be chemically consistent across parent and metabolite.

RT window: Confirmed RT ± RT_TOL_S seconds. The tolerance is set conservatively (30 s) to account for run-to-run gradient drift within the same study. It can be tightened if multiple peaks appear within the window.

We use Chromatograms::chromExtract() to extract EICs in a single pass over the Spectra object. A peak table defines one extraction window per (role × file): rtMin/rtMax from the confirmed-RT windows and mzMin/mzMax from the target mass ± PPM tolerance. 8.7 Peak boundaries and narrow re-extraction

# via a fresh peak_tbl so the result has the same `dataOrigin` ordering

narrow_extract <- function(chr, role, mz_centre, ppm) {
  bnd <- Chromatograms::peakBoundary(chr)            # n x 2 matrix
  cd  <- chromData(chr)

         is.finite(bnd[, "right_boundary"])

    role       = role,
    msLevel    = 1L,
    dataOrigin = cd[["dataOrigin"]][ok],

    rtMax      = bnd[ok, "right_boundary"] + BOUND_PAD_S,

    mzMax      = mz_centre * (1 + ppm * 1e-6),
    stringsAsFactors = FALSE)

}

8.9 FWHM outlier check

Within the same dataset the chromatographic peak width should be roughly constant — the gradient is fixed, the same compound elutes the same way across injections. A file whose FWHM departs strongly from the median (here: > 3 × MAD) usually means the EIC is integrating two fused peaks, baseline noise, or a co-eluting isobar — i.e., the AUC for that file is suspect and should be flagged before it enters the ratio.

flag_fwhm <- function(df, col) {
  v   <- df[[col]]
  med <- median(v, na.rm = TRUE)
  mad <- stats::mad(v, na.rm = TRUE)
  if (!is.finite(mad) || mad == 0)
    return(rep(FALSE, length(v)))
  abs(v - med) > 3 * mad

8.12 Ratio handling — the parent-only file

In this prototype run we have at least one file with parent detected but no metabolite. Biologically, for CYP2C19 phenotyping, that profile is informative: it points to a poor metabolizer (the substrate is present, the enzyme is not turning it over). Three options for scoring it:

  1. Drop the sample. Loses real signal — poor metabolizers are exactly the phenotype we want to detect.
  2. Set ratio = 1. Wrong: implies parent ≈ metabolite, which is the profile of an extensive metabolizer. This would invert the biological meaning.
  3. Treat as right-censored. Keep the sample, note detection_tier == "parent_only", and in the stats stage use either (a) a detection-status logistic test (parent_only count vs both count per group) or (b) impute met_auc to the per-dataset noise floor (e.g. half the smallest detected met_auc) and label the resulting ratio as a lower bound.

9 Metadata limitations and unsupervised exploration

What we resolved per file for MTBLS1866 is the rule, not the exception. Across the tier-B curated datasets, only a minority of public deposits ship the biological covariates (sex, age, country, treatment, BMI, ethnicity) that a phenotyping analysis would normally adjust for. The MASST/Pan-ReDU ATTRIBUTE_* columns are usable when the depositor populated them but are empty for most MetaboLights and Metabolomics Workbench studies, and the linked papers — when they exist — typically report demographics as per-arm aggregates (Table 1 sex/age) rather than as per-sample tables joinable to file names.

For our analysis this has two concrete consequences:

  1. Unadjustable confounding. A ratio difference we observe between two datasets could reflect a real biological effect or simply a difference in sex / age / ancestry composition that we cannot model. Within-dataset contrasts (e.g. the 5-level COVID severity here) are insulated from this; cross-dataset meta-analysis is not.
  2. Limited stratification. Within most deposits the only available stratifier is the study’s primary design factor (case vs control, severity grade, …). Secondary effects we would normally investigate — e.g. is the CYP2C19 ratio sex-dependent in this cohort? — are not testable from the public data alone.

9.1 Unsupervised structure as a metadata-gap diagnostic

A practical workaround is to run an unsupervised analysis on the per-file metric matrix (par_auc, met_auc, par_fwhm, met_fwhm, log2_ratio) and check whether the resulting structure aligns with the available metadata. If a clear cluster split emerges that does not track health_status (the only per-file factor we have), that split is evidence of a latent covariate the deposit does not expose — which is itself a finding worth reporting. The unsupervised view becomes a missing-metadata diagnostic, not just an exploratory plot.

#     by per-column sd, which is NaN if any NA is present.

both_for_pca <- as.data.frame(
  sample_tbl[sample_tbl$detection_tier == "both", ])
both_for_pca$.row_id <- seq_len(nrow(both_for_pca))

pc_cols <- c("par_auc","met_auc","par_fwhm","met_fwhm","log2_ratio")
pc_mat  <- as.matrix(both_for_pca[, pc_cols])
rownames(pc_mat) <- as.character(both_for_pca$.row_id)

# Keep non-constant columns
inf_cols <- apply(pc_mat, 2, function(x) {
  v <- stats::sd(x, na.rm = TRUE); !is.na(v) && v > 0 })
pc_mat <- pc_mat[, inf_cols, drop = FALSE]

# Drop rows with any NA across the kept columns
pc_mat <- pc_mat[stats::complete.cases(pc_mat), , drop = FALSE]

if (nrow(pc_mat) >= 5 && ncol(pc_mat) >= 2) {
  pc      <- stats::prcomp(pc_mat, scale. = TRUE)
  row_ids <- as.integer(rownames(pc$x))         # safely tracked
  pc_df   <- cbind(
    as.data.frame(pc$x[, 1:min(2, ncol(pc$x)), drop = FALSE]),
    both_for_pca[row_ids,
                 c("subject_id","health_status","country"),
                 drop = FALSE])

  ggplot(pc_df, aes(PC1, PC2,
                    colour = health_status,
                    label  = subject_id)) +
    geom_point(size = 3, alpha = 0.85) +
    geom_text(vjust = -0.7, size = 3, show.legend = FALSE) +
    labs(title    = paste(dataset_proto, "— PCA of EIC metrics"),
         subtitle = "Cluster splits not tracking health_status hint at unmeasured covariates",
         caption  = paste("n =", nrow(pc_df), "subjects | available factors:",
                          "health_status, body_site, country (constant)")) +
    theme_bw() + theme(legend.position = "bottom")
} else {
  cat("Skipping PCA — need >=5 `both` samples and >=2 non-constant metrics",
      "(have", nrow(pc_mat), "rows,", ncol(pc_mat), "informative cols)\n")
}

9.2 A note for the paper

The same diagnostic, run dataset by dataset, becomes a quantitative argument for richer mandatory metadata in public metabolomics repositories: how many datasets show unsupervised structure that the available metadata cannot explain? A handful would already justify proposing a minimum-metadata standard (at least BiologicalSex, AgeInYears, Country, and a structured treatment_history field where ethical) at the level of MetaboLights / Workbench submission templates and Pan-ReDU re-annotation. This finding is a free side benefit of the pipeline — we get it from the same metric matrix that feeds the ratio analysis, no extra computation.
